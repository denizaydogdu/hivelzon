## 5. Geri çekme

`A2-R-CIN-03` için `WITHDRAW` (`reason=OTHER`):

- Durum **WITHDRAWN**, gerekçe kaydedildi.
- Açık katalog A2: **9 → 8**, kimlik listede **yok**.
- Geri çekilen sürümde `allowedActions` **boş** (yeni sürüm olmadan yeniden yayınlanamaz).

durumuna döndürüldü (`lock_version` artırıldı); açık katalog yeniden **9**. **Üretimde geri
çekilen içerik yeni sürüm olmadan geri alınmaz**; bu SQL yalnız yerel prova kolaylığıdır.

## 6. Bulgular

### F1 — Uygulama backend yayın durumunu okumuyordu (çözüldü, 2026-10-21)

- İlk provada `reelCatalogProvider` → `ContentSource.listReels()` → `HttpContentSource` →
  **`/reels/index.json`** (geliştirme sunucusu, dosya sistemini tarar) okuyordu;
  `/api/v1/catalog/reels` uygulamada **hiç çağrılmıyordu**. Geri çekilen video cihazda
  oynatılabiliyordu.
- **Düzeltme:** `HttpContentSource` varsayılan olarak backend kataloğunu okur
  (`REEL_CATALOG_URL`, varsayılan `http://127.0.0.1:8080/api/v1/catalog/reels`), sayfalar
  (`size=100`), her kaydın `packageBaseUrl`'ini saklar ve `reel.json`/medya adreslerini oradan
  kurar. Yayında olmayan kimlik `loadReel`'de **oynatılmaz**; backend hatasında dosya kataloğuna
  sessizce düşülmez (fail-closed). Dosya kataloğu yalnız `REEL_CATALOG_URL=''` ile demo içindir.
- **Uçtan uca kanıt (simülatör):** yeni kurulumda seçki `CIN-01 · SPO-01 · BOK-01` geldi.
  `A1-R-CIN-01` backend'de geri çekildi → açık katalog A1 **9 → 8**; uygulama yeniden açıldığında
  seçki **`CIN-02 · SPO-01 · BOK-01`** oldu (üç video korunur). Geliştirme sunucusunun dosya
  kataloğunda CIN-01 hâlâ duruyordu; yani davranış backend'den geliyor.

### F2 — Alan eşlemesi (çözüldü)

- Backend `ReelItem`'a `family` eklendi (günlük seçkide "aynı aile bir kez" ve "Tekrar" için).
- İstemci `categoryTr`'yi koddan türetir, `sourceType`'ı `standalone` varsayar, `status`'ı

  kullanılmıyor; tam paket `reel.json`'undan geliyor.

### F3 — Geri çekme sonrası işletim

`WITHDRAWN` durumunda aksiyon kalmıyor; geri alma yeni sürüm gerektiriyor. Bu bilinçli bir
politika, ancak H-092 sırasında yanlışlıkla geri çekilen bir videonun geri gelmesi için
"yeni sürüm yükle → onayla → yayınla" adımı gerekecek. Pilot kitine not düşülmeli.

### F4 — Katalogdan düşen videonun yedeği (bulundu ve düzeltildi)

Geri çekilen video backend kataloğunda **hiç yoksa** günlük seçki onu çıkarıyor ama yerine
aynı seviye-kategoriden yedek koymuyordu (seçki 3 → 2 video). Nedeni, yedeğin kategorisinin
katalog özetinden okunması; kayıt yokken kategori boş kalıyordu. Düzeltme: kategori saklanan
kimlikten okunur (`A1-R-CIN-02` → `CIN`, `reelCategoryFromId`). Regresyon testi:
`mobile/test/features/discover/reel_selection_test.dart` → "katalogdan tamamen düşen içerik de
aynı kategoriden yedeklenir". Simülatörde CIN-01 geri çekilince CIN-02 kondu.

## 8. Tekrar çalıştırma

```sh
docker compose up -d --wait
cd backend && mvn -o -q -DskipTests package
HIVELZON_DB_URL=jdbc:postgresql://localhost:5435/hivelzon \
HIVELZON_CATALOG_REELS_IMPORT_ROOT=/Users/felece/Dev/hiVelzon/reeller \
HIVELZON_JWT_SECRET=... HIVELZON_OTP_PEPPER=... \
java -jar target/hivelzon-backend-0.0.1-SNAPSHOT.jar
```

Giriş: `POST /api/v1/auth/email/start` → kodu Mailpit `127.0.0.1:8027` üzerinden al →
`POST /api/v1/auth/email/verify`. Editör rolü: `UPDATE users SET role='EDITOR' WHERE email=...`.
Sonra sırasıyla içe aktarma → `APPROVE` → `PUBLISH` → `GET /api/v1/catalog/reels` →
`WITHDRAW` → katalogda yoklaması.

Uygulama (simülatör) backend kataloğunu varsayılan okur:

```sh
cd mobile && flutter run -d "hiVelzon iPhone 17" --dart-define=HV_START_ROUTE=/kesfet
# İstenirse: --dart-define=REEL_CATALOG_URL=http://127.0.0.1:8080/api/v1/catalog/reels
```
